HEAVY CODING

AI agents do not lie on purpose — they hallucinate success.
This workflow makes every claim pay a toll: an exit code or nothing.

v1.0.0 · first public release MIT Bash + Python · zero dependencies 14 gates github.com/PoorThoth/heavy-coding

The problem is not capability — it is verification

An agent reports “done” from the same context that produced the bug. Prompts that ask for honesty, self-review by the same model, and green CI on the wrong tests all fail for one reason: the judge is the defendant. Nothing in the loop can be wrong and still pass if the judge is a machine-checkable fact.

What this is

A coding session wrapped in 14 checkpoints. Each one can only be passed by something a machine can verify: a test that really executed, a diff line that really ran, a report whose file:line really exists. The agent’s prose is never evidence — only rc=0 on an artifact is.

05 Why it holds up — and what it cost to build

Five rules the design refuses to break

  1. Self-reports do not count. Executor output becomes evidence only when a command returns rc=0 on a machine-checkable artifact. “Verified”, “should work”, “looks good” are not results.
  2. A red baseline is data, not failure. Real repositories arrive red. Record the red set once, then fail only on new reds — a gate that cries wolf is ignored within a week.
  3. Exemptions are explicit and versioned. Untestable files go into .diffcovignore with a reason, in the diff. Thresholds are never quietly lowered.
  4. Gates about gates are tested in a sandbox. A checker cannot validate itself: inject a known failure, watch it go red, fix, watch it go green.
  5. Scope the measurement to the ticket. git diff HEAD includes other people’s uncommitted work; measuring it produces a meaningless number.

Start in 60 seconds

Nothing to configure: clone, install, open a ticket. Only the delegation step needs a key — all 14 gates run offline.

$ git clone https://github.com/PoorThoth/heavy-coding
$ cd heavy-coding && ./install.sh
$ wfctl task . my-first-ticket "add retry to fetch_user"
$ wfctl deleg . .agents/tasks/my-first-ticket/brief.md
$ wfctl verify . # tests · patch coverage · convergence · ledger
