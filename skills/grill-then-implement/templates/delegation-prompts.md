# 委托 Prompt 模板（Superpowers 实现阶段）

> 使用：替换 <占位符> 后交给**执行端**——**主力 Pi**：`pi --provider deepseek --model deepseek-v4-flash:low -p "<任务书>"`（或 `wfctl deleg <dir> prompt.txt`，长任务书走 stdin）；**备用 opencode**（MCP/插件依赖任务）：`opencode run "<任务书>" --pure`。
> ⚠️ 铁律：执行端调用**无状态**（Pi `-p` / opencode `run` 都不继承上次会话），单会话完整上下文一次给全。分阶段调用会导致任务漂移（实测）。

## 🚨 执行环境优先级（所有模板必须附加；高于任何技能默认流程）

> 2026-10-08 实测来源：Pi 加载官方 superpowers 6.4.2 后，`brainstorming` 要求"任何创作前必须用它"并设审批门（`skills/brainstorming/SKILL.md:3,48-49`），
> `writing-plans` 固定把计划写到 `docs/superpowers/plans/`（`skills/writing-plans/SKILL.md:16`），
> `using-git-worktrees` 默认会**问**要不要开隔离 worktree（`skills/using-git-worktrees/SKILL.md:41-43`）。
> 实测 Pi 的思考原文是 "The user instructions take precedence" —— 它会以任务书为准，但**每次都要花一段推理纠结**；写成规则可省掉这段并堵住无人值守的两个断链点。

```
【执行环境优先级】本任务书高于任何技能（superpowers 等）的默认流程：
1. 冲突时以本任务书为准：可以读/用技能（如 TDD），但不许因技能停下、不许请求审批、不许等确认——一次跑完。
2. 产物一律写进 .agents/（任务书指定的 <slug> 目录）；不要创建 docs/superpowers/plans|specs 之类目录。
3. worktree / merge / push / 部署 / 改生产库：一律"不做 + 报告"，由宿主（Hermes）决定。
4. TDD、systematic-debugging 这类与本任务书同向的技能内容直接用，不必宣布。
```

> 自动化：`wfctl deleg` 已把这段（`templates/task/preamble.txt`）**自动前置**到 prompt；裸 `pi -p` 调用需手工带上。
> 需要做对照实验时用 `WF_NO_PREAMBLE=1` 关掉它。


## 任务书五段式（v3.5——结构固定，缺段必出问题）

> **+ 阶段 0 段（2026-10-09 新增）**：五段式之前先有【现成答案检索】——三组查询 + 结论 + 来源（URL/版本/日期）；
> 属仓库内部结构问题或已确认无现成答案 ⇒ 写 `现成答案检索: 不适用（原因…）` / `已查（查了…无答案）`。
> `wfctl deleg` 默认拒绝没有这段记录的任务书（`wfctl lookup` 生成 `lookup.md` 骨架；`WF_NO_LOOKUP=1` 应急跳过）。

| 段 | 作用 | 缺了会怎样 |
|---|---|---|
| ① 目标 | 一句话说清做到什么程度（含"严禁改变什么"） | "优化一下" → 任务漂移 |
| ② 事实与资料 | 精确行号/文件路径/已侦察结论/现有脚手架清单 | 让 agent 自己翻仓库 → 它去探索相邻目录被权限拦、或重复侦察烧完上下文 |
| ③ 步骤 | 编号可执行，明确"别扩大范围" | "顺便重构一下" → 改动面失控 |
| ④ 硬性约束（禁令清单） | 不做清单 + 卡住怎么办 | 只说"要做好" → 它顺手改了数值行为 |
| ⑤ 交付物与验收 | 交什么、怎么判、谁判 | "改完告诉我" → 只能听自述 |

## 🚨 所有模板必须附加的通用段

### 【环境上下文】（Hermes 委托前填好——agent 无法自行发现这些信息）
```
- 端口约定: <后端端口>（如 8081，8080 被占用）/ <前端端口>（如 5175，5173 被占用）
- 本机已有服务: <如 docker 容器占 8080/3000，不要动它们>
- 代理: HTTP_PROXY=http://127.0.0.1:7890（仅当 agent 自己需要外网/交易所 API 时才给）
```

### 🚨 最小凭据暴露（v3.5 修订——原模板把 DSN 明文写进 prompt，agent 看得见）

**原则：agent 不需要的凭据，就不要出现在它的上下文里。**

| 情况 | 做法 |
|---|---|
| 推荐（默认） | **不给任何凭据**——agent 只写代码 + 跑**离线/桩**测试；连库、起服务、端到端验收全部由 **Hermes 亲自做** |
| agent 必须连库跑集成测试 | 只给**最小集合**（如只读账号 DSN），并注明"仅限本地测试" |
| 任何情况 | 不把 DSN/API key 写进 agent 可能提交的文件；不让它读 `.env` |

> 2026-09-13 实测：委托 225 行核心重构**未给任何凭据**——agent 只跑 `go build` + 包测试；父代理另跑"真实场景金标准对拍"（脚本从启动脚本读 DSN 且**掩码不打印**），一次通过。

### 【权限规则】（2026-08-05 固化；2026-10-08 标注端别）
> **端别**：下面 1-5 条两端通用，但「会被权限 auto-reject 中断整个委托」只对 **opencode 备用端**成立。
> **Pi 无内置权限系统**（以启动用户权限运行，不拦命令）⇒ 不越界、临时文件写项目内、**禁止部署/push/删库**这类约束对 Pi 更要紧——它没有门禁替你兜底。
1. ⚠️ 只允许访问当前项目目录内的文件（<项目绝对路径>）——不要读/写项目外任何目录，禁止 `cd ..` 与 `..` 相对路径
2. 需要项目外资源（凭据/其他仓库文件/数据库/外部命令）时：先尝试用终端命令替代（如 cp/mysql 客户端），终端也受限则**不要放弃**——把"需要什么、卡在哪一步"写进最终报告，Hermes 会接手处理
3. 禁止读 .env——需要环境变量值直接看【环境上下文】段
4. 调试用临时文件写在**项目目录内**（如 `./tmp/`）并用完删除，**禁止写 `/tmp` 或系统 Temp**（会被权限 auto-reject 中断整个委托）
5. 测试/构建命令失败时先看错误信息自己修复，连续 2 次失败才报告

### 交付物四字段（v3.5——不信自述，看证据）
```
【交付物】完成后必须**原样贴出**（不要转述、不要改写成"全部通过"）：
1. `git diff --stat` 原文
2. 测试/构建输出原文
3. 改动的文件与行号范围
4. ⚠️ 自评风险点：哪些改动**可能改变行为**？哪些地方你自己没把握？
   （例："我把 X 改名了，如果别处也引用这个符号，语义可能变"）
   —— 这段最有价值：你标出的疑点会成为验收重点。
```

### 硬性约束（禁令清单，按任务类型勾选）
```
- ❌ 不改任何数值行为（撮合/费率/滑点/阈值/统计口径），不许"顺手优化"
- ❌ 不重构、不改名、不排版与任务无关的代码
- ❌ 不部署、不 push、不碰生产
- ❌ 不删除/修改既有测试断言
- ✅ 做不到就**停下如实报告卡点**（fail loud），不要糊过去
```

## 模板 D：Bug 修复（三段式：assess → fix → test）★v4.2

> 对标 spec-kit 的 bug 扩展：**诊断/修复/验证三段分离**，产物落 `.agents/bugs/<slug>/`，
> **终判只能是 verified / partial / failed**（“缺验证 ≠ 修好了”）。
> 疑难 bug（一次定位不到根因）**先只下 assess 一段**，拿到根因再下 fix+test。

```
【任务】修复 <项目名> 的 bug：<现象>（slug: <短名，如 login-crash>）
【复现路径】<触发命令/步骤——必须是用户实际路径>
【期望行为】<修复后应该怎样>
【背景事实】（已侦察：<文件:行 / 最近改动 / 报错原文>，不要重复探索）

【交付物三件（缺一不算完成）】
1. `.agents/bugs/<slug>/assess.md` —— 复现记录（命令+输出原文）、**根因**（不是猜测，写清因果链）、
   影响面（哪些调用方/数据/线上表现）、修复方案与风险。
2. `.agents/bugs/<slug>/fix.md` —— 先加一个复现症状的失败测试（贴 RED 输出）→ 最小改动修根因 →
   贴 GREEN 输出 → 原有测试零回归（贴全量测试输出）。
3. `.agents/bugs/<slug>/test.md` —— 复跑**原始症状**（同【复现路径】）+ 全量回归 + **终判**
   `verified` / `partial` / `failed`（附证据命令与输出）。

【硬性约束】
- 不许叠补丁绕过根因；修不动就停下报告卡点，禁“应该没问题”这类无证据结论。
- 不做无关重构；不改测试断言来“让它过”；不部署、不 push。
- 每个可验证阶段 commit（子代理单次运行有时限，未提交=白干）。

【交付物四字段】<git show --stat / 测试原文 / 行号 / 自评风险点>
```

## 模板 F：核心重构 / 机械搬移（要求行为不变）★v3.5

> 适用：把引擎/核心逻辑的一整段**原样**搬到别处、抽公共结构、拆函数——**唯一目标是不改变行为**。
> 验收不看"测试绿"，看**行为指纹逐位一致**（Pitfall 87）。

```
【任务】在 <仓库绝对路径> 完成 <重构名>：<一句话>。**严禁改变任何行为**。

【事实与资料】（已侦察，直接用，**不要重复探索**）
- 目标位置：<文件>:<起止行>（共 N 行），循环头在 <行号>，闭合在 <行号>
- 关键事实：<如"主循环本来就是时间驱动：每步用 marketDataAt(snapshots,&idx,t) 取快照"——省掉 agent 自己摸结构>
- 标识符归属分类：<哪些归 A 结构 / 哪些归 B 结构 / 哪些保持不变（并注明为什么）>
- 可复用脚手架：<已提交的结构体/函数/文件清单——别重写>

【步骤】
1. <补字段 / 新建结构>
2. 把 <起止行> 的循环体**原样搬进** func <名字>(...)（**从原处读出文本再放进去，不要手抄**；按上表改名）
3. <回填调用点>——目标是新旧路径**共用同一段代码**，不许留下两份重复体
4. 验证：`go build ./...` 干净 + 以下包全绿：<包列表>

【硬性约束】
- 不改任何数值行为（撮合/费率/滑点/熔断/统计口径）
- 不重构、不改名、不排版无关代码；不增删测试断言
- 不部署、不 push；做不到就**停下如实报告卡点**
- 改完先 gofmt，再看 `git diff` **逐条核对语义**（尤其整行调用替换——有人把 Stop 误写成 Start）

【提交纪律】**每完成一个可验证阶段就 commit**（不要等全部通过再提交）——子代理单次运行有时限
（本机实测约 600s），超时/中断会留下未提交的改动（本次：225 行抽取已完成且可编译，
但因未 commit 而需主控重新评估）：也不要一个任务里塞过多验证（本次任务 = 抽取 + 6 包回归，
刚好在最后一步撞上限）。宁可拆成「改完即 commit → 再跑回归」两步。

【交付物】<四字段>（含自评风险点）

【注意】端到端行为对拍由我负责：我会用**改动前记录的行为指纹 sha256** 逐位比对（逐笔明细 + 结果曲线 + 关键统计）。你不用连数据库、不用起服务。
```

## 模板 G：收敛核对（converge）★v4.2

> 对标 spec-kit `/speckit-converge`。只出报告、不改代码；判定为**未收敛**就回 G3 修。

```
【任务】对 <仓库绝对路径> 的 <本次改动/spec 路径> 做一次收敛核对，**只出报告、不改代码**。
【输入】SPEC.md（或任务书）+ `git log <基线>..HEAD`
【要求】三向核对，逐条给证据：
  1. SPEC → 代码：每条 User Story/验收清单 → 实现位置（文件:行）+ 该代码**是否被调用**（贴调用点）
  2. 代码 → SPEC：本次 diff 里有没有 SPEC 没写的隐性行为（默认值/隐式契约/边界放宽）——逐条列出
  3. SPEC → 测试：每条验收判据 → 对应测试名 + 最近一次真实运行结果
【输出】`.agents/converge-<日期>.md`：核对表 + **缺口清单**（每条带复现/证据）+ 判定 **Converged / 未收敛**
【硬性约束】不确定的标 UNKNOWN 并列求证方式；**禁止**把缺口写成“下期做”就判 Converged。
```

## 模板 H：想法评估（三态：go / needs-clarification / kill）★v4.2

> 对标 spec-kit assess 扩展。无代码库也能跑；**kill 也是产出**。

```
【任务】评估这个想法值不值得做：<原话>（无代码库也能跑）
【要查的】① 外部先例：别人怎么做的、效果与成本（给链接与数字）② 我们侧前提：需要的数据/接口/权限，现在有没有
  ③ 最小可行形态与工作量 ④ 主要风险与失败模式
【输出】`.agents/assess/<slug>.md`（≤ 1 页）：证据（带引用）→ 最小形态 → 风险 → **结论**：
  go（交给 G1 质询）/ needs-clarification（缺哪条信息、找谁要）/ kill（什么证据下会复活）
【硬性约束】结论必须是三态之一，**不许“再看看”**；kill 要写复活条件。
```
