# 质询质量评估清单（Grill Quality Gate）

> 在阶段 1（Pocock 质询）完成后、进入 spec 之前，用本清单评估质询质量。
> 不合格 → 补一轮定向质询。实测 3 次质询产出 20-24 个问题。

## 必查维度（8 项，每项必须至少 1 个问题）

| # | 维度 | 必问内容 | 漏了会怎样 |
|---|------|---------|-----------|
| 1 | **输入/数据源** | 数据从哪来？格式？文件/API/DB？中英列名？ | 解析层全错 |
| 2 | **判定/规则边界** | 什么算"正常/成功"？阈值？边界值？ | 核心逻辑错误 |
| 3 | **网络/环境** | 需要代理吗？国内环境？TLS/认证？ | 跑不起来 |
| 4 | **容错/重试** | 失败怎么办？重试几次？退避？ | 静默失败/假死 |
| 5 | **频率/性能** | 轮询间隔？并发？数据量级？ | 架构过度/不足 |
| 6 | **输出/格式** | 什么格式？纯文本/JSON/文件？谁消费？ | 交付物不匹配 |
| 7 | **扩展性** | 以后要支持多币种/多对象/多语言吗？ | 重构成本高 |
| 8 | **技术约束** | 语言版本？纯标准库？依赖限制？ | 环境不兼容 |

## 评分标准

- **通过**（≥6 项覆盖）：进入 spec 阶段
- **补问**（4-5 项）：对缺失维度补一轮定向质询（`请补充质询：<缺失维度> 相关的问题`）
- **重质询**（<4 项）：质询质量差，换措辞重新质询（`请重新质询，重点关注：<缺失维度清单>`）

## 实测基准（2026-08-01）

| 任务 | 问题数 | 亮点问题（超出预期的） |
|------|--------|----------------------|
| 资金费率监控 | 20 | 防抖(Q11)、代理(Q9)、结算倒计时 |
| 交易复盘工具 | 24 | FIFO配对(Q18-19)、强平标记(Q9)、中英列名(Q3) |
| Go 健康检查 | 22 | TLS跳过证书(Q15)、重定向(Q17)、并发顺序(Q22) |

**结论**：DeepSeek V4 Pro 的质询质量稳定达标（8/8 维度全覆盖）。小模型（免费档）质询质量未验证，建议只用于明确需求。

## 使用方式

```bash
# 质询完成后，人工对照 8 维度清单核验
# 通过 → wfctl.sh deleg 进入实现阶段
# 缺维度 → 补一轮：opencode run '请补充质询以下维度：<列表>' --pure
```
