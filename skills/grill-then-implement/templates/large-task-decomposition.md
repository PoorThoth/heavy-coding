# 超长任务分块策略（Large Task Decomposition）

> 当任务超过单会话承载（opencode run 上下文放不下 / 预计 >2 小时）时使用。
> 原则：**宁可多几次交接，不要一次失败**。

## 判定标准（触发分块）

- [ ] 预计实现 > 10 个模块/文件
- [ ] 需求描述 > 1 屏（50 行 prompt 装不下）
- [ ] 依赖多个子系统（DB + API + 前端）
- [ ] 单次 run 预计 > 30 分钟

## 分块模式（按任务类型）

### 模式 A：纵向切片（推荐，最稳）
每个块 = 一个**端到端可用**的垂直切片（切穿所有层），块之间通过交接协议衔接。

```
块1: 数据层（schema + 读取 + 测试）
块2: 业务层（核心逻辑 + 测试）← 依赖块1
块3: API 层（接口 + 测试）← 依赖块2
块4: 前端/CLI（展示 + 集成测试）← 依赖块3
```

每块独立：`wfctl.sh handoff` 打 tag → 新会话从 tag 继续。

### 模式 B：水平分层（DB 明确时）
每个块 = 一个技术层，适合已有清晰分层架构。

```
块1: schema + migrations
块2: repository/DAO 层
块3: service 层
块4: handler/controller 层
```

### 模式 C：功能分区（多个独立功能）
每个块 = 一个独立功能（互不依赖，可并行）。

```
块1: 功能 A（独立）
块2: 功能 B（独立）← 可与块1 并行（见并行开发注意事项）
块3: 集成
```

## 块间衔接（关键）

1. **每块结束必须**：测试全过 + `wfctl.sh handoff "feat: 块N完成"`（自动打 tag）
2. **下一块 prompt 必须包含**：上一块的 HANDOFF.md 路径 + 本块明确范围（`只实现 X，不碰 Y`）
3. **每块 ≤ 单会话**：一个块放不下就再切（宁可 6 个小块，不要 3 个中块）
4. **并行块注意**：独立功能可并行，但必须（a）不同目录/分支（b）prompt 加"禁止访问其他目录"约束（c）合并时配置类文件冲突用 `--ours` 解决

## 分块后的验证

```bash
# 每块完成后
wfctl.sh verify-setup <dir> "<测试命令>"
# 全部块完成后（集成验证）
wfctl.sh verify-setup <dir> "<全量测试命令>"
```

## 反模式

- ❌ 一个超大 prompt 硬塞（上下文溢出 → 任务漂移）
- ❌ 按"文件数量"均分（块间依赖不清 → 集成地狱）
- ❌ 块间靠"记住"衔接（必须 HANDOFF.md + tag）
